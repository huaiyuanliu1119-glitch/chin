前言

排序演算法是演算法課程中的核心主題，因為它直接體現了資料規模、設計策略與時間複雜度之間的關係。

同樣是將資料由小到大排列，不同方法在小型資料集上可能差異不大，但在大型資料集上往往會拉出數十倍甚至數百倍的執行時間差距。本作業的重點不只是寫出五種排序，而是把 理論分析 與 實際量測 放在同一個框架下比較，理解演算法選擇如何影響最終效能。

五個排序法介紹

以下依序說明五種排序法的基本原理、操作方式與適用特性。

Bubble Sort

氣泡排序

反覆比較相鄰元素並交換位置，使較大的數逐步往尾端移動。每完成一輪，至少有一個元素會回到正確位置。

  • 操作方式直觀，適合教學展示。
  • 若資料幾乎已排序，可透過提早停止降低實際耗時。
  • 屬於穩定排序，但大規模資料效率差。
Selection Sort

選擇排序

每一輪從未排序區間挑出最小值，放到目前位置。比較次數固定，但交換次數相對少。

  • 流程簡單，便於理解「逐步確定最小值」的策略。
  • 無論原始資料是否接近排序完成，時間表現都接近固定。
  • 通常不穩定，且整體效率仍屬 O(n^2)。
Insertion Sort

插入排序

維持一段已排序區間，依序將新元素插入適當位置，像整理手上的撲克牌一樣。

  • 對於小型資料或幾乎已排序資料表現很好。
  • 屬於穩定排序，且原地操作，空間需求低。
  • 當資料量變大，移動成本會迅速上升。
Merge Sort

合併排序

採用分治法，先把陣列拆成更小的子陣列，再把已排序子陣列逐步合併回來。

  • 時間複雜度穩定維持在 O(n log n)。
  • 適合需要穩定排序與可預期效能的情境。
  • 缺點是需要額外的暫存空間。
Quick Sort

快速排序

選定一個樞紐值，將資料分成小於樞紐與大於樞紐兩側，再遞迴完成排序。

  • 平均情況下速度極快，是實務上常見的高效排序策略。
  • 原地分割使空間效率佳。
  • 若樞紐選得很差，最差時間會退化為 O(n^2)。

複雜度分析

排序法除了程式寫法不同，更關鍵的是時間成長率與額外空間需求。

排序法 最佳時間 平均時間 最差時間 空間複雜度 穩定性
氣泡排序 O(n) O(n^2) O(n^2) O(1) 穩定
選擇排序 O(n^2) O(n^2) O(n^2) O(1) 不穩定
插入排序 O(n) O(n^2) O(n^2) O(1) 穩定
合併排序 O(n log n) O(n log n) O(n log n) O(n) 穩定
快速排序 O(n log n) O(n log n) O(n^2) O(log n) 不穩定

O(n^2) 類型

氣泡、選擇與插入排序在資料量翻倍時，所需操作次數接近平方成長，因此只適合小型資料或教學情境。

O(n log n) 類型

合併與快速排序能在較大規模維持優勢，是實務中更常用的主流方法。

理論重點

時間複雜度決定成長趨勢，空間複雜度則影響記憶體使用；選演算法時通常要兩者一起看。

實驗設計

實驗目標是觀察不同資料規模下，五種排序法的實際時間差距是否符合理論。

資料規模 100、500、1000、2000、4000
資料內容 0 到 99999 的隨機整數，使用同一組輸入複製給各排序法。
量測方式 每個規模重複 3 次，使用 performance.now() 計算平均毫秒數。

為了避免 O(n^2) 演算法在瀏覽器內執行時間過長，本頁將最大規模控制在 4000 筆。雖然不是極大資料量，但已足以看出二次方成長與對數線性成長之間的差異。

結果比較與分析

理論與實驗通常會呈現一致趨勢，但實際數字仍會受到執行環境與常數因子影響。

小規模資料

當 n 不大時，所有排序法的耗時都很短，差異不容易放大。這也是為什麼小型作業或面試手寫題常先從簡單排序法開始。

中大型資料

一旦資料量進入數千筆，氣泡、選擇與插入排序的成本開始快速上升，而合併排序與快速排序仍保持明顯優勢。

實務選擇

如果要求穩定排序，合併排序通常更安全；若追求平均效能，快速排序通常是更常見的選擇。

心得與結論

排序演算法的核心價值，不在於背誦步驟，而在於理解資料規模改變時，效能如何被複雜度主導。

心得一

透過實驗可以很清楚地看到，O(n^2) 與 O(n log n) 的差異在資料量變大後會迅速放大，這比單看公式更有感。

心得二

簡單排序法並非沒有價值。它們在概念教學、小型資料、部分排序資料或交換成本高的情境下仍然有實用性。

心得三

選擇演算法時不能只看平均速度，還要考慮穩定性、額外空間與輸入資料特性，這也是實作與理論之間最重要的連結。
