合併排序

合併排序使用分治法，把陣列一分為二直到只剩單一元素，再把這些已排序的小陣列逐步合併回來。它是理論和實務都很重要的 O(n log n) 排序法。

合併排序不論最佳、平均或最差情況都維持 O(n log n)，效能相當穩定，但要用額外空間來完成合併。

  • 穩定排序
  • 需要額外空間，空間複雜度 O(n)
  • 適合大資料與需要穩定性的情境
核心操作先遞迴切分，再把兩個已排序子陣列合併成更大的已排序陣列。
穩定性合併時可保留相同元素的先後順序，因此屬於穩定排序。
常見印象複雜度漂亮且穩定，但需要額外記憶體，常見於理論分析與外部排序。

基本原理與操作方式

合併排序的重點是分治。它先把原始陣列一直對半切，直到每個子陣列只剩一個元素，此時每個子陣列都可視為已排序。接著再從最小單位開始兩兩合併，逐步得到完整的排序結果。

  1. 把陣列對半分割成左半與右半。
  2. 對左右子陣列遞迴執行同樣操作。
  3. 當子陣列長度為 1 時停止切分。
  4. 依大小比較左右陣列元素，合併成新的已排序陣列。

它不是靠大量交換完成排序，而是靠有系統的拆分與合併，把問題拆小後再組回來。

function mergeSort(arr) { if (arr.length <= 1) return arr; const mid = Math.floor(arr.length / 2); const left = mergeSort(arr.slice(0, mid)); const right = mergeSort(arr.slice(mid)); return merge(left, right); }

穩定性穩定

由於每一層總共處理 n 個元素，而切分深度大約是 log n，因此時間複雜度穩定維持在 O(n log n)。代價是每次合併都需要暫存空間。

適用情境

當資料量大、需要穩定排序，或希望效能表現可預期時，合併排序通常是很可靠的選擇。

不適用情境

若環境對記憶體空間很敏感，或希望完全原地排序，合併排序就不一定是最佳方案。

觀察重點

看它時要抓住兩個動作：先拆小，再由小往大合併。這個節奏和前面三種簡單排序法完全不同。
