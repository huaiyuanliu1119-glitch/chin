選擇排序

選擇排序每一輪都從未排序區間找出最小值，再放到前面固定位置。它不像氣泡排序一樣頻繁交換，而是把焦點放在「先選出最適合的元素」。

O(n²)

選擇排序的比較次數幾乎固定，不會因資料原本接近有序就明顯變快，但它的交換次數通常比氣泡排序少。

  • 不穩定排序
  • 原地排序，空間複雜度 O(1)
  • 適合理解每輪挑選最小值的流程
核心操作 每一輪找出未排序區間中的最小值，然後與前端位置交換。
穩定性 交換最小值時可能改變相同元素相對順序，因此通常不穩定。
常見印象 比較次數固定、交換較少，邏輯簡單但整體效率仍不適合大型資料。

基本原理與操作方式

選擇排序會把陣列切成已排序區與未排序區。每一輪都從未排序區掃描一遍，找到最小元素，然後把它交換到未排序區開頭。這樣做完第一輪後，最左邊的位置就固定為全陣列最小值。

  1. 從目前位置開始，先假設它就是最小值。
  2. 掃描後面的元素，持續更新最小值索引。
  3. 掃描結束後，把最小值換到目前位置。
  4. 往右移動一格，重複同樣流程直到完成排序。

它的特色不是「一路把錯的資料交換回去」，而是「每輪都先找出最該放到前面的那個元素」。

for (let i = 0; i < n - 1; i++) { let selectedIndex = i; for (let j = i + 1; j < n; j++) { if (arr[j] < arr[selectedIndex]) { selectedIndex = j; } } [arr[i], arr[selectedIndex]] = [arr[selectedIndex], arr[i]]; }

複雜度分析

項目 結果
最佳時間 O(n²)
平均時間 O(n²)
最差時間 O(n²)
空間複雜度 O(1)
穩定性 不穩定

它與資料初始排列的關係不大，因為每輪都還是會完整掃描剩餘元素。優點是交換次數只有每輪一次左右，缺點是比較成本依然很高。

適用情境

當交換操作成本高於比較成本，或需要非常直觀的「每輪選最小值」展示時，選擇排序很適合教學。

不適用情境

資料量一大，它依舊需要大量比較；如果要處理實際應用的大陣列，通常不會優先考慮它。

觀察重點

每輪結束時，最左邊未排序位置一定被填入當前最小值，已排序區會穩定向右擴張。

範例解析

以 29, 10, 14, 37, 13 為例，第一輪會先找出 10 放到最前面；第二輪再從剩下資料中找 13 放到第二個位置。這種「找最小再交換」就是選擇排序的節奏。
